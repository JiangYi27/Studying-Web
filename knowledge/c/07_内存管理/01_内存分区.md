# 内存分区

## 内存分区概述

C 程序在运行时，内存被划分为几个不同的区域，每个区域有不同的用途和特征。

## 五大区划分总览

C 程序的内存地址空间通常划分为 **五大区**：

| 分区 | 存放内容 | 分配/释放 | 典型大小 |
|------|----------|-----------|----------|
| 代码段（Text） | 机器指令、只读常量 | 编译时固定 | 固定 |
| 数据段（Data） | 已初始化的全局/静态变量 | 程序启动/结束 | 固定 |
| BSS 段 | 未初始化的全局/静态变量（自动清零） | 程序启动/结束 | 固定 |
| 堆区（Heap） | 动态分配的内存（malloc 等） | 程序员手动 | 大（可达数 GB） |
| 栈区（Stack） | 局部变量、函数参数、返回地址 | 函数调用/返回自动 | 较小（通常几 MB） |

> **注意**：栈和堆共用一段地址空间，**栈从高地址向下增长**，**堆从低地址向上增长**，两者相向而行，最大限度利用内存。

## 代码区（Text Segment）

### 特征

- **只读**：存储程序的机器指令，不能修改
- **共享**：多个进程运行同一程序时共享代码区
- **固定大小**：在程序编译时确定

### 内容

- 编译后的机器指令
- 只读常量（字符串常量等）

```c
// 代码区存储编译后的指令
printf("Hello");  // "Hello" 字符串常量存储在只读数据段
```

## 数据区（Data Segment）

数据区分为两部分：全局/静态区和常量区。

### 全局/静态区（Initialized Data Segment）

#### 特征

- **存储已初始化的全局变量和静态变量**
- **程序启动时分配，程序结束时释放**
- **可读写**

#### 示例

```c
int global_var = 100;        // 全局变量，存储在全局/静态区
static int static_var = 200; // 静态变量，存储在全局/静态区

void func(void) {
    static int count = 0;    // 静态局部变量，存储在全局/静态区
    count++;
}
```

### 未初始化数据区（BSS Segment）

#### 特征

- **存储未初始化的全局变量和静态变量**
- **程序启动时自动初始化为 0**
- **不占用可执行文件的空间**

#### 示例

```c
int uninitialized_global;    // 存储在 BSS 段，初始值为 0
static int uninitialized_static; // 存储在 BSS 段，初始值为 0
```

### 常量区（Read-Only Data Segment）

#### 特征

- **存储字符串常量和 const 修饰的常量**
- **只读**

#### 示例

```c
const int MAX = 100;         // const 常量，可能存储在常量区
char *str = "Hello";         // "Hello" 存储在常量区
```

## 栈区（Stack）

### 特征

- **自动管理**：由编译器自动分配和释放
- **后进先出（LIFO）**：函数调用时分配，返回时释放
- **大小有限**：通常几 MB（Linux 默认 8 MB）
- **访问速度快**：CPU 寄存器直接支持

### 栈上分配的内容

- 局部变量
- 函数参数
- 返回地址
- 寄存器保存

### 示例

```c
void func(void) {
    int local_var = 10;  // 存储在栈区
    int arr[100];        // 存储在栈区

    // 函数返回时，local_var 和 arr 自动释放
}
```

### 栈溢出

```c
void recursive_func(int n) {
    int arr[1000];  // 每次递归调用分配 4KB 栈空间
    if (n > 0) {
        recursive_func(n - 1);  // 递归深度过大导致栈溢出
    }
}

int main(void) {
    recursive_func(100000);  // 可能导致栈溢出
    return 0;
}
```

### 避免栈溢出

1. **避免过深的递归**
2. **避免在栈上分配过大的数组**
3. **使用动态内存分配（堆）**

## 堆区（Heap）

### 特征

- **手动管理**：程序员负责分配和释放
- **动态分配**：运行时根据需要分配
- **大小灵活**：受限于系统可用内存
- **访问速度较慢**：需要系统调用

### 堆上分配的内容

- 动态分配的内存
- 动态数据结构（链表、树等）

### 示例

```c
#include <stdlib.h>

int main(void) {
    // 在堆上分配内存
    int *arr = (int *)malloc(100 * sizeof(int));
    if (arr != NULL) {
        arr[0] = 10;
        // 使用 arr...
        free(arr);  // 释放内存
        arr = NULL;
    }

    return 0;
}
```

## 内存分区对比

| 分区 | 管理方式 | 生命周期 | 访问速度 | 大小限制 |
|------|----------|----------|----------|----------|
| 代码区 | 自动 | 程序运行期间 | 快 | 固定 |
| 全局/静态区 | 自动 | 程序运行期间 | 快 | 固定 |
| BSS 段 | 自动 | 程序运行期间 | 快 | 固定 |
| 常量区 | 自动 | 程序运行期间 | 快 | 固定 |
| 栈区 | 自动 | 函数调用期间 | 快 | 较小（几 MB） |
| 堆区 | 手动 | 程序员控制 | 较慢 | 较大（系统内存） |

## 内存布局示例

```
高地址
┌─────────────────────────┐
│        栈区              │ ← 向下增长
│   (局部变量、参数)       │
├─────────────────────────┤
│         ↓ 空闲空间 ↓     │
├─────────────────────────┤
│         ↑ 堆区 ↑         │ ← 向上增长
│   (动态分配的内存)       │
├─────────────────────────┤
│        BSS 段            │ ← 未初始化全局/静态变量
├─────────────────────────┤
│        数据段            │ ← 已初始化全局/静态变量
├─────────────────────────┤
│        常量区            │ ← 字符串常量、const 常量
├─────────────────────────┤
│        代码区            │ ← 机器指令
└─────────────────────────┘
低地址
```

### 常见平台的地址大小

指针（地址）所占字节数随平台不同而不同：

| 平台 | 指针大小 | 可寻址空间 | 典型系统 |
|------|----------|-----------|----------|
| 32 位 | 4 字节 | 4 GB | x86、老版本 Windows/Linux |
| 64 位 | 8 字节 | 巨大（理论 16 EB） | x86-64、ARM64 主流系统 |

```c
#include <stdio.h>

int main(void) {
    printf("指针大小：%zu 字节\n", sizeof(void *));  // 32 位输出 4，64 位输出 8
    printf("int 大小：%zu 字节\n", sizeof(int));
    return 0;
}
```

> **注意**：正因为地址大小因平台而异，涉及地址和长度的代码应使用 `size_t`、`ptrdiff_t` 等可移植类型，避免硬编码 4 或 8。

## 栈与堆的对比

| 特性 | 栈 | 堆 |
|------|-----|-----|
| 管理方式 | 自动管理 | 手动管理 |
| 分配速度 | 快 | 较慢 |
| 释放方式 | 自动 | 手动（free） |
| 大小限制 | 较小 | 较大 |
| 碎片问题 | 无 | 可能产生碎片 |
| 生命周期 | 函数调用期间 | 程序员控制 |
| 访问效率 | 高 | 较低 |

## 内存管理最佳实践

1. **优先使用栈分配**（速度快、自动管理）
2. **大内存使用堆分配**（避免栈溢出）
3. **始终检查 malloc 返回值**
4. **malloc 后必须 free**
5. **free 后将指针设为 NULL**
6. **避免内存泄漏**
7. **避免重复释放**
