# 静态与动态库

## 静态库（.a）

### 基本概念

静态库在编译时被链接到可执行文件中，生成的可执行文件包含库的完整副本。

### 创建静态库

```bash
# 编译目标文件
gcc -c file1.c -o file1.o
gcc -c file2.c -o file2.o

# 创建静态库
ar rcs libmylib.a file1.o file2.o
```

### 使用静态库

```bash
gcc main.c -L. -lmylib -o program
```

### 静态库的特点

| 特性 | 说明 |
|------|------|
| 文件扩展名 | `.a`（Linux）/ `.lib`（Windows） |
| 链接时机 | 编译时 |
| 可执行文件大小 | 较大（包含库的副本） |
| 内存占用 | 每个进程独立加载 |
| 更新方式 | 重新编译程序 |
| 部署 | 无需额外文件 |

## 动态库（.so）

### 基本概念

动态库在程序运行时被加载，多个程序可以共享同一份库代码。

### 创建动态库

```bash
# 编译位置无关代码
gcc -fPIC -c file1.c -o file1.o
gcc -fPIC -c file2.c -o file2.o

# 创建动态库
gcc -shared -o libmylib.so file1.o file2.o
```

### 使用动态库

```bash
# 编译时链接
gcc main.c -L. -lmylib -o program

# 运行时需要库文件
export LD_LIBRARY_PATH=.:$LD_LIBRARY_PATH
./program
```

### 动态库的特点

| 特性 | 说明 |
|------|------|
| 文件扩展名 | `.so`（Linux）/ `.dll`（Windows） |
| 链接时机 | 运行时 |
| 可执行文件大小 | 较小（不包含库代码） |
| 内存占用 | 多个进程共享 |
| 更新方式 | 替换库文件即可 |
| 部署 | 需要部署库文件 |

## 静态库 vs 动态库对比

| 特性 | 静态库 | 动态库 |
|------|--------|--------|
| 文件扩展名 | `.a` | `.so` |
| 链接时机 | 编译时 | 运行时 |
| 可执行文件大小 | 大 | 小 |
| 内存占用 | 独立 | 共享 |
| 更新方式 | 重新编译 | 替换库文件 |
| 部署 | 简单 | 需要库文件 |
| 启动速度 | 快 | 稍慢 |
| 版本管理 | 困难 | 容易 |

## Windows 平台下的库

Windows 下的库体系与 Linux 略有差异，常用 MinGW（GCC）或 MSVC 两种工具链：

| 项目 | Linux (GCC) | Windows MinGW | Windows MSVC |
|------|-------------|---------------|--------------|
| 静态库 | `libfoo.a` | `libfoo.a` | `foo.lib` |
| 动态库 | `libfoo.so` | `foo.dll`（含 `.dll.a` 导入库） | `foo.dll` + `foo.lib`（导入库） |
| 编译 | `ar rcs` | `ar rcs` | `lib /OUT:foo.lib` |

**MinGW（GCC）工具链**：用法与 Linux 基本一致，动态库后缀为 `.dll`。

```bash
# MinGW 下创建静态库
gcc -c math_utils.c -o math_utils.o
ar rcs libmathutils.a math_utils.o

# MinGW 下创建动态库（.dll）
gcc -shared -o mathutils.dll math_utils.o

# 使用动态库
gcc main.c -L. -lmathutils -o program.exe
```

**MSVC 工具链**：使用 `cl` 编译器，动态库通常配合导入库（Import Library）使用。

```bash
# MSVC 下创建静态库
cl /c math_utils.c
lib /OUT:math_utils.lib math_utils.obj

# MSVC 下创建动态库（生成 .dll 和 .lib 导入库）
cl /LD math_utils.c -o math_utils.dll
```

**Windows 动态库的导出**：Windows 下动态库中的函数需要显式导出才能被外部调用。常用 `__declspec(dllexport)` 修饰：

```c
// math_utils.h
#ifdef __cplusplus
extern "C" {
#endif

__declspec(dllexport) int add(int a, int b);
__declspec(dllexport) int subtract(int a, int b);

#ifdef __cplusplus
}
#endif
```

MSVC 生成动态库时，被 `__declspec(dllexport)` 修饰的函数会被自动加入导入库，链接时无需再手动指定导出表。

## 库的管理

### 查看库中的符号

```bash
# 查看静态库中的目标文件
ar t libmylib.a

# 查看库中的符号
nm libmylib.a

# 查看动态库中的符号
nm -D libmylib.so
```

### 查看库的依赖

```bash
# 查看可执行文件依赖的动态库
ldd ./program
```

## 链接器选项

### -L 和 -l

```bash
# -L 指定库搜索路径
# -l 指定库名（自动添加 lib 前缀和 .a/.so 后缀）
gcc main.c -L./lib -lmylib -o program
```

### -static 和 -shared

```bash
# 静态链接
gcc -static main.c -lmylib -o program

# 动态链接（默认）
gcc main.c -lmylib -o program
```

### -fPIC

`-fPIC`（Position Independent Code）生成位置无关代码，是创建动态库的必要选项。

```bash
gcc -fPIC -c file.c -o file.o
```

## 库的版本管理

### Linux 动态库版本命名

```
libfoo.so.1.2.3
├── libfoo.so -> libfoo.so.1  （软链接，链接器使用）
├── libfoo.so.1 -> libfoo.so.1.2.3  （软链接）
└── libfoo.so.1.2.3  （实际文件）
```

### soname

动态库的 `soname` 记录了库的版本信息。

```bash
# 查看 soname
objdump -p libfoo.so.1.2.3 | grep SONAME
```

## 创建和使用库的完整示例

### 创建数学库

```c
// math_utils.h
#ifndef MATH_UTILS_H
#define MATH_UTILS_H

int add(int a, int b);
int subtract(int a, int b);

#endif
```

```c
// math_utils.c
#include "math_utils.h"

int add(int a, int b) {
    return a + b;
}

int subtract(int a, int b) {
    return a - b;
}
```

### 编译静态库

```bash
gcc -c math_utils.c -o math_utils.o
ar rcs libmathutils.a math_utils.o
```

### 编译动态库

```bash
gcc -fPIC -c math_utils.c -o math_utils.o
gcc -shared -o libmathutils.so math_utils.o
```

### 使用库

```c
// main.c
#include <stdio.h>
#include "math_utils.h"

int main(void) {
    printf("3 + 5 = %d\n", add(3, 5));
    printf("10 - 4 = %d\n", subtract(10, 4));
    return 0;
}
```

```bash
# 使用静态库
gcc main.c -L. -lmathutils -o program_static

# 使用动态库
gcc main.c -L. -lmathutils -o program_dynamic
export LD_LIBRARY_PATH=.:$LD_LIBRARY_PATH
./program_dynamic
```

## 库的最佳实践

1. **优先使用动态库**（便于更新和节省内存）
2. **使用版本号管理库**
3. **使用 `soname` 确保兼容性**
4. **使用 `ldd` 检查依赖**
5. **使用 `nm` 检查符号**
6. **使用 `-fPIC` 编译动态库**
7. **使用 `-Wl,-rpath` 指定运行时库路径**
