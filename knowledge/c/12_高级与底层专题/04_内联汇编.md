# 内联汇编（扩展）

## GCC 风格内联汇编

### 基本语法

GCC 提供了内联汇编扩展，允许在 C 代码中直接嵌入汇编指令。

```c
asm volatile (
    "汇编指令"
    : 输出操作数
    : 输入操作数
    : 被修改的寄存器
);
```

### 关键字说明

- **`asm`**：内联汇编关键字
- **`__asm__`**：`asm` 的别名，在严格遵循 ANSI C 标准（如 `-std=c99` 或 `-ansi`）时，`asm` 会被当作普通标识符导致编译错误，此时必须使用 `__asm__`
- **`volatile`**：防止编译器优化掉汇编代码；`__volatile__` 是 `volatile` 的别名，用法相同
- **输出操作数**：汇编代码的输出
- **输入操作数**：汇编代码的输入
- **被修改的寄存器**：汇编代码修改的寄存器列表

```c
// 在 -std=c99 或 -ansi 模式下必须用 __asm__ 和 __volatile__
__asm__ __volatile__ ("nop");
```

### asm 与 __asm__ 的选择

| 写法 | 适用场景 |
|------|----------|
| `asm` | 默认模式（非严格标准）下使用 |
| `__asm__` | `-std=c99`、`-ansi` 等严格标准模式下必须使用 |

> 在 Visual Studio 中，`__asm`（单下划线，无空格块）用于 MSVC 的 x86 内联汇编，与 GCC 的 `__asm__` 语法不同。

## 基本示例

### 简单的 NOP 指令

```c
asm volatile ("nop");
```

### 获取 CPU 时间戳

```c
unsigned int get_timestamp(void) {
    unsigned int timestamp;
    asm volatile (
        "rdtsc"
        : "=a" (timestamp)
        :
        : "edx"
    );
    return timestamp;
}
```

### 交换两个变量

```c
void swap(int *a, int *b) {
    asm volatile (
        "xchg %0, %1"
        : "+r" (*a)
        : "r" (*b)
    );
}
```

## 操作数约束

### 约束字符

| 约束 | 说明 |
|------|------|
| `"r"` | 通用寄存器 |
| `"m"` | 内存地址 |
| `"i"` | 立即数（编译期常量） |
| `"n"` | 立即数（0~255 的整型常量） |
| `"g"` | 寄存器、内存或立即数 |
| `"c"` | 寄存器 `ecx` |
| `"a"` | 寄存器 `eax` |
| `"d"` | 寄存器 `edx` |
| `"S"` | 寄存器 `esi` |
| `"D"` | 寄存器 `edi` |

### 输出约束

| 约束 | 说明 |
|------|------|
| `"=r"` | 输出到寄存器 |
| `"=m"` | 输出到内存 |
| `"+r"` | 输入输出到寄存器 |
| `"+m"` | 输入输出到内存 |

### 示例

```c
int result;
asm volatile (
    "addl %1, %2"
    : "=r" (result)
    : "r" (a), "r" (b)
);
```

## 寄存器变量

### 使用特定寄存器

```c
int value = 42;
int result;

asm volatile (
    "movl %1, %%eax\n\t"
    "addl $1, %%eax\n\t"
    "movl %%eax, %0"
    : "=r" (result)
    : "r" (value)
    : "%eax"
);
```

### 寄存器命名

在 GCC 内联汇编的指令模板中，寄存器名前需要加 `%%` 前缀（如 `%%eax`），因为单个 `%` 被保留用于操作数（`%0`、`%1`）。只有独立的汇编源文件（`.s` 文件）中才直接使用 `%eax`。

- 指令模板内：`%%eax`、`%%ebx`
- 操作数引用：`%0`、`%1`、`%2`……

## 内存操作数

### 直接内存访问

```c
int value = 42;
asm volatile (
    "movl %0, %%eax"
    :
    : "m" (value)
    : "%eax"
);
```

### 内存屏障

```c
// 读屏障
asm volatile ("lfence" ::: "memory");

// 写屏障
asm volatile ("sfence" ::: "memory");

// 完全屏障
asm volatile ("mfence" ::: "memory");

// GCC 内存屏障
asm volatile ("" ::: "memory");
```

## 内联汇编的最佳实践

1. **使用 `volatile` 防止优化**
2. **明确列出被修改的寄存器**
3. **使用约束而非硬编码寄存器**
4. **避免在关键路径使用内联汇编**
5. **优先使用 C 语言实现**
6. **测试不同编译器版本的行为**

## 内联汇编的常见陷阱

### 陷阱 1：忘记列出被修改的寄存器

```c
// 正确：在第三个冒号后列出被修改的寄存器
asm volatile ("movl $1, %%eax" ::: "eax");

// 错误：没有告诉编译器 eax 被修改，编译器可能误用 eax 保存其他值
asm volatile ("movl $1, %%eax");
```

### 陷阱 2：操作数顺序错误

AT&T 语法中，源操作数在前，目标操作数在后。

```c
// AT&T 语法：源 -> 目标
asm volatile ("addl %1, %0" : "=r" (result) : "r" (a));
// 等价于 result = result + a;
```

### 陷阱 3：忘记内存屏障

```c
// 错误：编译器可能重排内存访问
asm volatile ("movl %0, %%eax" : : "m" (value));

// 正确：使用内存屏障
asm volatile ("" ::: "memory");
```

## 平台相关内联汇编

### x86 汇编

```c
// 获取 CPU ID
asm volatile (
    "cpuid"
    : "=a" (eax), "=b" (ebx), "=c" (ecx), "=d" (edx)
    : "a" (level)
);
```

### ARM 汇编

```c
// 获取 CPSR 寄存器
unsigned int cpsr;
asm volatile (
    "mrs %0, cpsr"
    : "=r" (cpsr)
);
```

## 内联汇编的应用场景

1. **性能关键代码**（如 SIMD 指令）
2. **硬件寄存器访问**（嵌入式开发）
3. **系统调用**（操作系统开发）
4. **原子操作**（无锁编程）
5. **特殊指令**（如 `cpuid`、`rdtsc`）

## 替代方案

### 使用编译器内置函数

GCC 提供了许多内置函数，可以替代内联汇编。

```c
// 替代内联汇编的 __builtin_ 函数
int clz = __builtin_clz(x);      // 计算前导零
int ctz = __builtin_ctz(x);      // 计算尾随零
int popcount = __builtin_popcount(x);  // 计算置位位数
```

### 使用标准库函数

```c
#include <stdlib.h>

// 替代内联汇编的 qsort
qsort(arr, n, sizeof(int), compare);
```

## 内联汇编与可移植性

内联汇编是平台相关的，会降低代码的可移植性。

1. **GCC 内联汇编**：x86、ARM 等
2. **MSVC 内联汇编**：x86 仅支持
3. **不同编译器语法不同**

建议：
- **优先使用 C 语言实现**
- **使用编译器内置函数**
- **将平台相关代码隔离到单独的文件**
- **使用条件编译**
