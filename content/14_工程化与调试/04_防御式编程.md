# 防御式编程

## 防御式编程概述

防御式编程是一种编程方法论，旨在使程序在面对意外输入、错误条件和恶意攻击时能够优雅地处理，而不是崩溃或产生不可预测的行为。

## 错误码处理

### 基本模式

```c
typedef enum {
    SUCCESS = 0,
    ERR_NULL_PTR,
    ERR_INVALID_INPUT,
    ERR_IO_ERROR,
    ERR_OUT_OF_MEMORY
} ErrorCode;

const char *error_message(ErrorCode code) {
    switch (code) {
        case SUCCESS:
            return "成功";
        case ERR_NULL_PTR:
            return "空指针";
        case ERR_INVALID_INPUT:
            return "无效输入";
        case ERR_IO_ERROR:
            return "I/O 错误";
        case ERR_OUT_OF_MEMORY:
            return "内存不足";
        default:
            return "未知错误";
    }
}
```

### 函数返回错误码

```c
ErrorCode safe_open(const char *filename, FILE **fp) {
    if (fp == NULL) {
        return ERR_NULL_PTR;
    }

    *fp = fopen(filename, "r");
    if (*fp == NULL) {
        return ERR_IO_ERROR;
    }

    return SUCCESS;
}

int main(void) {
    FILE *fp;
    ErrorCode code = safe_open("test.txt", &fp);

    if (code != SUCCESS) {
        fprintf(stderr, "错误: %s\n", error_message(code));
        return 1;
    }

    // 使用文件...
    fclose(fp);
    return 0;
}
```

## errno 全局变量

### 基本用法

`errno` 是定义在 `<errno.h>` 中的全局变量，存储最近一次系统调用或库函数的错误码。

```c
#include <errno.h>
#include <stdio.h>
#include <string.h>

FILE *fp = fopen("nonexistent.txt", "r");
if (fp == NULL) {
    printf("错误码: %d\n", errno);
    printf("错误信息: %s\n", strerror(errno));
    perror("fopen");  // 输出 "fopen: No such file or directory"
}
```

### 常见 errno 值

| 错误码 | 常量 | 说明 |
|--------|------|------|
| 1 | EPERM | 操作不被允许 |
| 2 | ENOENT | 文件或目录不存在 |
| 5 | EIO | I/O 错误 |
| 13 | EACCES | 权限不足 |
| 22 | EINVAL | 无效参数 |
| 24 | EMFILE | 打开文件数过多 |

### perror() 函数

```c
void perror(const char *s);
```

输出格式：`s: 错误信息\n`

```c
FILE *fp = fopen("nonexistent.txt", "r");
if (fp == NULL) {
    perror("fopen");  // 输出 "fopen: No such file or directory"
}
```

## assert() 断言

### 基本用法

```c
#include <assert.h>

int divide(int a, int b) {
    assert(b != 0);  // 断言 b 不为零
    return a / b;
}
```

### 断言的工作原理

- **调试模式**：断言失败时输出错误信息并终止程序
- **发布模式**：定义 `NDEBUG` 后，断言被忽略

```c
#define NDEBUG
#include <assert.h>
// 此时 assert 宏被定义为 ((void)0)
```

### 断言的最佳实践

1. **用于检查不可能发生的情况**
2. **用于检查函数的前置条件**
3. **不要用断言替代错误处理**
4. **发布版本中禁用断言**
5. **断言失败应立即终止程序**

## 防御式编程的最佳实践

### 1. 检查所有输入参数

```c
int safe_divide(int a, int b, int *result) {
    if (result == NULL) {
        return -1;  // 错误：空指针
    }
    if (b == 0) {
        return -2;  // 错误：除零
    }
    *result = a / b;
    return 0;  // 成功
}
```

### 2. 检查所有函数返回值

```c
FILE *fp = fopen("test.txt", "r");
if (fp == NULL) {
    perror("fopen");
    return 1;
}
```

### 3. 使用 const 保护不修改的数据

```c
void print_string(const char *str) {
    // str 指向的数据不会被修改
    printf("%s\n", str);
}
```

### 4. 避免未定义行为

```c
// 错误：数组越界
int arr[5];
arr[10] = 1;  // 未定义行为

// 正确：检查边界
if (index >= 0 && index < 5) {
    arr[index] = 1;
}
```

### 5. 使用静态分析工具

```bash
# 使用 clang 静态分析器
clang --analyze program.c

# 使用 cppcheck
cppcheck program.c

# 使用 gcc 警告选项
gcc -Wall -Wextra -Werror program.c
```

### 6. 避免魔法数字

魔法数字（Magic Number）指代码中含义不明的裸数字常量，如 `if (score >= 90)` 中的 `90`。魔法数字易写错、难维护，改一处可能漏掉另一处。应使用**宏常量**、**const 常量**或**枚举**赋予其明确含义。

```c
// 错误：多处裸数字，含义不明且难以统一修改
if (score >= 90) { printf("优秀\n"); }
if (score >= 80) { printf("良好\n"); }

// 正确：使用宏/const 定义常量
#define EXCELLENT_THRESHOLD 90
#define GOOD_THRESHOLD      80

if (score >= EXCELLENT_THRESHOLD) { printf("优秀\n"); }
if (score >= GOOD_THRESHOLD)      { printf("良好\n"); }
```

```c
// 数组大小使用常量而非裸数字
#define MAX_STUDENTS 100

int scores[MAX_STUDENTS];
for (int i = 0; i < MAX_STUDENTS; i++) {
    // ...
}

// 状态码使用枚举，避免含义不明的整数
typedef enum {
    STATE_IDLE,
    STATE_RUNNING,
    STATE_DONE
} Status;
```

**什么时候可以保留字面量**：`0`、`1`、`-1`、`'\0'`、`NULL` 等自解释的数值，以及数学中的自然常数（如 `2`、`3`、`100` 表示百分比）可直接使用；其余含义不直观的数值都应命名。

## 错误处理模式

### 模式 1：返回错误码

```c
ErrorCode safe_function(int *result) {
    if (result == NULL) {
        return ERR_NULL_PTR;
    }
    *result = 42;
    return SUCCESS;
}
```

### 模式 2：返回布尔值

```c
bool safe_function(int *result) {
    if (result == NULL) {
        return false;
    }
    *result = 42;
    return true;
}
```

### 模式 3：全局错误状态

```c
static ErrorCode last_error = SUCCESS;

ErrorCode get_last_error(void) {
    return last_error;
}

void set_error(ErrorCode code) {
    last_error = code;
}
```

### 模式 4：setjmp/longjmp 异常处理

```c
#include <setjmp.h>

jmp_buf error_env;

void risky_operation(void) {
    if (error_condition) {
        longjmp(error_env, 1);
    }
}

int main(void) {
    if (setjmp(error_env) == 0) {
        risky_operation();
    } else {
        // 错误处理
    }
    return 0;
}
```

## 常见防御式编程错误

### 1. 忽略返回值

```c
// 错误：忽略 fopen 的返回值
FILE *fp = fopen("test.txt", "r");
fprintf(fp, "Hello");  // 如果 fp 为 NULL，会导致段错误
```

### 2. 忽略边界检查

```c
// 错误：未检查数组边界
int arr[5];
arr[10] = 1;  // 缓冲区溢出
```

### 3. 使用未初始化的变量

```c
// 错误：使用未初始化的变量
int x;
printf("%d\n", x);  // x 的值不确定
```

### 4. 忘记释放内存

```c
// 错误：内存泄漏
int *p = (int *)malloc(100 * sizeof(int));
// 忘记 free(p);
```

### 5. 错误的类型转换

```c
// 错误：不安全的类型转换
int *p = malloc(sizeof(int));
float *fp = (float *)p;  // 错误的类型转换
```

## 防御式编程总结

| 技术 | 用途 |
|------|------|
| 错误码 | 函数返回值表示成功/失败 |
| errno | 系统级错误信息 |
| assert | 检查内部不变量 |
| const | 保护不修改的数据 |
| 边界检查 | 防止数组越界 |
| 空指针检查 | 防止空指针解引用 |
| 静态分析 | 自动检测潜在错误 |
| 单元测试 | 验证代码正确性 |
