# setjmp 与 longjmp

## 基本概念

`setjmp` 和 `longjmp` 提供了**非局部跳转**（non-local jump）机制，允许程序从一个函数直接跳到一个**外层函数**中预先设置好的位置，从而绕过一层层函数返回。它们常被用来实现跨函数错误处理与恢复。

需要包含头文件 `<setjmp.h>`。

## setjmp

### 基本语法

```c
#include <setjmp.h>

int setjmp(jmp_buf env);
```

### 功能

保存当前的执行环境（栈指针、寄存器、程序计数器 PC 等）到 `env` 中。`jmp_buf` 是一个数组类型，用来存放这些现场信息。`setjmp` 之后程序继续往下执行。

### 返回值

`setjmp` 会被调用**两次**并产生两个不同的结果：

- **首次直接调用**：返回 `0`，表示"环境已保存，这是设置点"。
- **之后由 longjmp 恢复回来**：返回这一次 `longjmp` 传入的第二个参数 `val`。因此一般用：

```c
if (setjmp(env) == 0) {
    // 第一次到达，正常执行
} else {
    // 从 longjmp 跳回来，此时进入错误处理
}
```

> **注意**：`setjmp` 只能作为"if、switch、三元表达式、条件表达式"等受限制的上下文中的独立表达式，因为它保存的是非普通的环境信息，直接把其返回值赋值给普通变量再后续判断是不可移植的。

## longjmp

### 基本语法

```c
void longjmp(jmp_buf env, int val);
```

### 功能

恢复 `setjmp` 保存到 `env` 的执行环境，使控制流跳转回**当初调用 `setjmp(env)` 的那个函数的那一处**。`env` 必须已被 `setjmp` 初始化过。

### 返回值/参数

- `val` 会被带回给 `setjmp`，作为其这一次的返回值。
- 若 `val` 为 `0`，标准规定会按 `1` 处理（因为 `0` 已被"首次调用"占用，无法区分）。

## 基本用法

```c
#include <stdio.h>
#include <setjmp.h>

jmp_buf env;

void function(void) {
    printf("在 function 中\n");
    longjmp(env, 1);  // 跳转回 setjmp 处
    printf("这行不会执行\n");
}

int main(void) {
    if (setjmp(env) == 0) {
        printf("首次调用 setjmp\n");
        function();
    } else {
        printf("从 longjmp 恢复\n");
    }

    return 0;
}
```

输出：
```
首次调用 setjmp
在 function 中
从 longjmp 恢复
```

## 错误处理示例

### 模拟异常处理

```c
#include <stdio.h>
#include <setjmp.h>
#include <stdlib.h>

jmp_buf error_env;

void risky_operation(void) {
    printf("执行危险操作...\n");

    // 模拟错误
    int error_code = 1;
    if (error_code != 0) {
        longjmp(error_env, error_code);
    }

    printf("操作成功\n");
}

int main(void) {
    int error = setjmp(error_env);

    if (error == 0) {
        // 正常执行
        risky_operation();
    } else {
        // 错误处理
        printf("发生错误，错误码: %d\n", error);
    }

    return 0;
}
```

### 多层错误处理

```c
#include <stdio.h>
#include <setjmp.h>

jmp_buf env;

void level3(void) {
    printf("Level 3: 发生错误\n");
    longjmp(env, 3);
}

void level2(void) {
    printf("Level 2: 调用 Level 3\n");
    level3();
    printf("Level 2: 这行不会执行\n");
}

void level1(void) {
    printf("Level 1: 调用 Level 2\n");
    level2();
    printf("Level 1: 这行不会执行\n");
}

int main(void) {
    if (setjmp(env) == 0) {
        level1();
    } else {
        printf("捕获到错误\n");
    }

    return 0;
}
```

## setjmp/longjmp 与 goto 的对比

| 特性 | setjmp/longjmp | goto |
|------|----------------|------|
| 跳转范围 | 跨函数 | 同一函数内 |
| 保存环境 | 保存完整执行环境 | 无 |
| 恢复现场 | 恢复栈指针等 | 无 |
| 用途 | 异常处理 | 错误清理 |

## setjmp/longjmp 的注意事项

### 1. 资源泄漏

`longjmp` 会跳过中间的代码，可能导致资源泄漏。

```c
void func(void) {
    FILE *fp = fopen("test.txt", "r");
    if (fp == NULL) {
        longjmp(env, 1);  // 文件未关闭！
    }
    // ...
    fclose(fp);  // longjmp 会跳过这行
}
```

### 2. 避免在 longjmp 后使用已跳过的变量

```c
void func(void) {
    int x = 10;
    longjmp(env, 1);
    // x 的值在 longjmp 后不确定
}
```

### 3. volatile 关键字

使用 `volatile` 修饰在 `longjmp` 后仍需保持的值。

```c
volatile int error_code = 0;

void func(void) {
    error_code = 1;
    longjmp(env, 1);
}
```

## 跨函数异常处理

### 模拟 try-catch

```c
#include <stdio.h>
#include <setjmp.h>
#include <stdlib.h>

jmp_buf exception_env;

typedef enum {
    EXC_NONE = 0,
    EXC_DIVISION_BY_ZERO,
    EXC_OUT_OF_MEMORY,
    EXC_UNKNOWN
} ExceptionType;

ExceptionType current_exception = EXC_NONE;

void throw_exception(ExceptionType type) {
    current_exception = type;
    longjmp(exception_env, 1);
}

void risky_division(int a, int b) {
    if (b == 0) {
        throw_exception(EXC_DIVISION_BY_ZERO);
    }
    printf("结果: %d\n", a / b);
}

int main(void) {
    if (setjmp(exception_env) == 0) {
        // try 块
        risky_division(10, 0);
        printf("这行不会执行\n");
    } else {
        // catch 块
        switch (current_exception) {
            case EXC_DIVISION_BY_ZERO:
                printf("捕获到除零错误\n");
                break;
            case EXC_OUT_OF_MEMORY:
                printf("捕获到内存不足错误\n");
                break;
            default:
                printf("捕获到未知错误\n");
                break;
        }
    }

    return 0;
}
```

## setjmp/longjmp 的最佳实践

1. **仅用于错误处理**
2. **确保资源正确释放**
3. **使用 volatile 修饰跨跳转的变量**
4. **避免在 longjmp 后使用已跳过的局部变量**
5. **优先使用结构化错误处理**（返回值、错误码）
6. **在 C++ 中，setjmp/longjmp 不支持栈展开**
