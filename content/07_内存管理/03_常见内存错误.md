# 常见内存错误

## 野指针

### 概念

野指针是指向无效内存地址的指针。与空指针不同，野指针指向的地址可能看起来有效，但访问它会导致未定义行为。

### 野指针的常见原因

#### 1. 未初始化的指针

```c
int *p;       // 野指针，指向随机地址
// *p = 10;   // 危险！未定义行为
```

#### 2. 已释放的内存

```c
int *p = (int *)malloc(sizeof(int));
free(p);
// p 现在是野指针
*p = 10;  // 危险！未定义行为
```

#### 3. 指针越界

```c
int arr[5];
int *p = arr + 10;  // 越界指针
// *p = 10;  // 危险！
```

#### 4. 返回局部变量的指针

```c
int *bad_func(void) {
    int x = 10;
    return &x;  // 错误！x 是局部变量，函数结束后内存被释放
}
```

### 避免野指针

1. **始终初始化指针**
   ```c
   int *p = NULL;  // 初始化为 NULL
   ```

2. **释放内存后将指针设为 NULL**
   ```c
   free(p);
   p = NULL;
   ```

3. **避免返回局部变量的地址**

4. **使用断言检查指针有效性**
   ```c
   #include <assert.h>
   assert(p != NULL);
   ```

## 悬垂指针（use-after-free）

### 概念

悬垂指针（野指针的一种）是指**内存已被释放，但指针仍保存着原地址**，之后又通过该指针访问内存。这属于"使用已释放的内存"（use-after-free），是典型的未定义行为。

```c
int *p = (int *)malloc(sizeof(int));
*p = 10;
free(p);        // 内存已释放
// *p = 20;     // 危险！p 是悬垂指针，访问已释放的内存
```

### 悬垂指针与空指针的区别

| 对比项 | 空指针 | 悬垂指针 |
|--------|--------|----------|
| 值 | NULL，可判断 | 已释放内存的原地址，无法判断 |
| 解引用 | 必然段错误 | 未定义行为，可能读回垃圾值、崩溃或被黑客利用 |

### 避免悬垂指针

1. **free 后立即置 NULL**，让指针变回可判断的空指针。
2. **统一约定"谁分配谁释放"**，避免多个指针指向同一块内存。
3. **释放后不要再次访问**该内存区域。

## 内存泄漏

### 概念

内存泄漏是指程序分配了内存但未能释放，导致内存占用不断增加。

### 常见原因

#### 1. 忘记释放内存

```c
void leak_example(void) {
    int *arr = (int *)malloc(100 * sizeof(int));
    // 忘记 free(arr)
    return;  // 内存泄漏！
}
```

#### 2. 重新赋值导致原内存丢失

```c
void leak_example2(void) {
    int *p = (int *)malloc(100 * sizeof(int));
    p = (int *)malloc(200 * sizeof(int));  // 原内存丢失，泄漏！
    free(p);
}
```

#### 3. 异常路径未释放

```c
void leak_example3(void) {
    int *p1 = (int *)malloc(100 * sizeof(int));
    int *p2 = (int *)malloc(200 * sizeof(int));

    if (p1 == NULL || p2 == NULL) {
        // 异常路径，未释放已分配的内存
        return;  // 内存泄漏！
    }

    // 正常路径
    free(p1);
    free(p2);
}
```

### 检测内存泄漏

#### 使用 Valgrind

```bash
valgrind --leak-check=full ./program
```

#### 使用 AddressSanitizer（ASan）

```bash
gcc -fsanitize=address -g program.c -o program
./program
```

### 避免内存泄漏

1. **配对使用 malloc/free**
2. **使用 goto 进行统一清理**
3. **使用资源管理工具**
4. **及时释放不再使用的内存**

```c
// 使用 goto 进行统一清理
int process_file(const char *filename) {
    FILE *fp = NULL;
    int *buffer = NULL;
    int result = -1;

    fp = fopen(filename, "r");
    if (fp == NULL) {
        goto cleanup;
    }

    buffer = (int *)malloc(100 * sizeof(int));
    if (buffer == NULL) {
        goto cleanup;
    }

    // 处理文件...
    result = 0;

cleanup:
    if (fp != NULL) {
        fclose(fp);
    }
    if (buffer != NULL) {
        free(buffer);
    }
    return result;
}
```

## 重复释放

### 概念

对同一块内存调用多次 `free` 会导致未定义行为。

### 示例

```c
int *p = (int *)malloc(sizeof(int));
free(p);
free(p);  // 错误！重复释放
```

### 避免重复释放

1. **释放后将指针设为 NULL**
   ```c
   free(p);
   p = NULL;
   // 再次 free(p) 是安全的（free(NULL) 是合法的）
   ```

2. **使用标志位记录是否已释放**

3. **使用智能指针模式**（C 语言中手动实现）

### 双重释放的后果

对同一块内存调用两次 `free` 会破坏堆管理器的空闲链表，可能导致程序崩溃（`double free` 报错）、数据损坏或更严重的安全漏洞。**free 后置 NULL 是防双重释放最有效的手段**——`free(NULL)` 是安全空操作。

## 内存越界访问

### 概念

对数组、缓冲区等连续内存访问时，**下标（或指针）超出了合法范围**，读写到不属于自己的内存。

```c
void func(void) {
    int arr[5] = {1, 2, 3, 4, 5};

    arr[5] = 100;    // 越界写！arr 只有下标 0~4
    printf("%d\n", arr[-1]);  // 越界读！下标不能为负
}
```

### 越界访问的后果

1. **数据被破坏**：写到别的变量/结构体的内存，悄悄改坏程序逻辑。
2. **程序崩溃**：访问到无权限的地址，触发段错误（Segmentation Fault）。
3. **安全漏洞**：缓冲区越界写是蠕虫和黑客攻击的主要途径（如"缓冲区溢出攻击"）。

### 避免内存越界

1. **遍历前确认边界**，循环条件写成 `i < n` 而不是 `i <= n`。
2. **使用安全字符串函数**（`strncpy`、`snprintf`、`fgets`）。
3. **访问前检查下标合法性**。

## 栈溢出

### 概念

栈溢出是指程序在栈上分配了过多的内存，导致栈空间耗尽。

### 常见原因

#### 1. 过深的递归

```c
void recursive_func(int n) {
    int arr[1000];  // 每次递归分配 4KB
    if (n > 0) {
        recursive_func(n - 1);  // 递归深度过大导致栈溢出
    }
}
```

#### 2. 过大的局部数组

```c
void func(void) {
    int arr[1000000];  // 分配 4MB，可能导致栈溢出
}
```

### 避免栈溢出

1. **避免过深的递归**（使用迭代替代）
2. **避免在栈上分配过大的数组**（使用动态分配）
3. **增加栈大小**（编译器选项或系统设置）
4. **使用尾递归优化**（如果编译器支持）

## 缓冲区溢出

### 概念

缓冲区溢出是指向缓冲区写入超出其容量的数据，覆盖相邻内存。

### 示例

```c
void vulnerable_func(void) {
    char buf[10];
    strcpy(buf, "This is a very long string");  // 缓冲区溢出！
}
```

### 避免缓冲区溢出

1. **使用 `strncpy` 替代 `strcpy`**
2. **使用 `snprintf` 替代 `sprintf`**
3. **使用 `fgets` 替代 `gets`**
4. **始终检查输入长度**

## 内存对齐问题

### 概念

内存对齐是指数据在内存中的地址必须是其大小的整数倍。

### 示例

```c
struct Example {
    char a;    // 1 字节
    int b;     // 4 字节，需要 4 字节对齐
    short c;   // 2 字节，需要 2 字节对齐
};

// 实际内存布局（32 位系统）：
// 偏移 0: a (1 字节)
// 偏移 1-3: 填充 (3 字节)
// 偏移 4-7: b (4 字节)
// 偏移 8-9: c (2 字节)
// 偏移 10-11: 填充 (2 字节)
// sizeof(struct Example) = 12 字节
```

### 控制内存对齐

```c
#pragma pack(1)  // 取消对齐，结构体大小为各成员之和
struct Packed {
    char a;    // 1 字节
    int b;     // 4 字节
    short c;   // 2 字节
};  // sizeof(struct Packed) = 7 字节
#pragma pack()  // 恢复默认对齐
```

## 内存错误总结

| 错误类型 | 原因 | 后果 | 避免方法 |
|----------|------|------|----------|
| 野指针 | 未初始化/已释放/越界 | 未定义行为 | 初始化指针，释放后设为 NULL |
| 悬垂指针 | 释放后仍通过原指针访问 | 未定义行为/崩溃 | free 后置 NULL，谁分配谁释放 |
| 内存泄漏 | 忘记释放内存 | 内存占用不断增加 | 配对 malloc/free |
| 重复释放 | 多次 free 同一内存 | 未定义行为 | 释放后设为 NULL |
| 内存越界 | 下标/指针超出合法范围 | 数据破坏/崩溃/安全漏洞 | 检查边界，使用安全函数 |
| 栈溢出 | 递归过深/局部数组过大 | 程序崩溃 | 使用迭代，避免大数组 |
| 缓冲区溢出 | 写入超出缓冲区 | 数据损坏/安全漏洞 | 使用安全函数，检查长度 |
| 内存对齐 | 访问未对齐地址 | 性能下降/崩溃 | 使用 offsetof，了解对齐规则 |

## Valgrind 排查内存错误

Valgrind 是 Linux 下最常用的内存检测工具，可检测内存泄漏、非法读写（越界、use-after-free）等问题。

```bash
# 编译时加 -g 保留调试信息
gcc -g -o program program.c

# 用 valgrind 运行，检查内存泄漏
valgrind --leak-check=full --show-leak-kinds=all ./program

# 重点关注输出中的三类信息：
#   1. Invalid read/write of size N    → 越界读写 / use-after-free
#   2. definitely lost                 → 确定的内存泄漏
#   3. heap summary                    → 泄漏字节总数
```

如果程序报了段错误，先用 `valgrind ./program` 运行，Valgrind 会直接指出是**哪一行代码**非法访问了内存。
